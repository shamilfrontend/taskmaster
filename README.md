# Taskmaster

Трекер задач в стиле Trello: проект — канбан-доска с колонками, карточками и релизами внутри команд. Ролевая модель, учёт бюджета проекта (ставки и часы) и аналитика.

**Статус:** в разработке.

**Стек:** Vue 3 + TypeScript, Pinia, axios / Express + Mongoose / MongoDB.

## Авторизация

Вход только через **Яндекс ID** (OAuth). Локальный логин/пароль не используется: аккаунт создаётся или подключается при первом входе через Яндекс.

После OAuth выдаётся JWT в **httpOnly cookie**, TTL 7 дней, без refresh в v1. Logout очищает cookie. Храним у пользователя: `yandexId`, `displayName`, `email`, `avatarUrl`.

## Сущности

| Сущность | Назначение |
| --- | --- |
| **Команда** | Рабочее пространство: участники и одна роль на человека. Пользователь может быть в нескольких командах |
| **Приглашение** | Одноразовая ссылка с токеном и ролью; приглашённый обязан войти через Яндекс |
| **Проект** | Принадлежит команде; одна канбан-доска (колонки, карточки, метки), опционально релизы и бюджет. При создании сразу открывается канбан с тремя колонками |
| **Доска** | Техническая сущность 1:1 с проектом; в UI не показывается |
| **Релиз** | Версия проекта: название, дата, статус planned/released; карточки прикрепляются к одному релизу |
| **Карточка** | Задача: один исполнитель, срок, оценка часов, списания, метки, комментарии; опционально релиз. Описания в v1 нет |
| **Роль** | Права только на уровне команды; наследуется всеми проектами |

## Роли

Роль задаётся один раз на команду и действует во всех её проектах.

| Действие | Owner | Admin | Member | Viewer |
| --- | --- | --- | --- | --- |
| Просмотр команды, проектов и релизов | да | да | да | да |
| Карточки (создание, правки, перемещение, релиз) | да | да | да | нет |
| Списание часов | любые | любые | свои карточки | нет |
| Участники и инвайты | да | да | нет | нет |
| Проекты, релизы, ставки | да | да | нет | нет |
| Бюджет: просмотр | да | да | нет | нет |
| Бюджет: изменение | да | нет | нет | нет |
| Удаление команды | да | нет | нет | нет |

Создатель команды становится Owner.

Admin создаёт проект с `budgetLimit = 0`; лимит задаёт только Owner.

## Правила

### Инвайт

- Ссылка одноразовая: после принятия токен недействителен
- Роль в инвайте: Admin / Member / Viewer. Owner через инвайт не выдаётся
- Без привязки к email: кто первый вошёл через Яндекс и открыл ссылку — тот вступает
- Уже в команде — повторно не вступает, ссылка сгорает
- Неиспользованный инвайт можно отозвать (Owner/Admin). Срок: 7 дней

### Доступ

Все участники команды видят все проекты и релизы.

- **Owner** — бюджет (чтение и запись) и ставки
- **Admin** — ставки (чтение и запись); бюджет только смотрит, не меняет
- **Member** — план/факт ₽ только на своих карточках; на проекте — только остаток. Чужие ставки и чужой факт ₽ скрыты
- **Viewer** — проект (канбан), карточки и релизы; без ставок, бюджета и остатка

### Участники

- Смена роли и исключение: Owner — любого; Admin — только Member/Viewer (не Owner и не другого Admin)
- Роль Owner через смену роли не назначается. Команда без Owner невозможна
- Выход из команды: Member/Viewer/Admin сами; Owner выйти не может
- Исключённый: `assigneeId` на его карточках → `null`, план = 0; списания остаются (снимок ставки)

### Карточка и списания

- Открывается модалкой/drawer поверх доски
- Списывает всегда текущий пользователь; в загрузке часы и ₽ идут на него
- Ставка в записи = его ставка в проекте на момент списания (персональная → роли → 0); пишем `rateSnapshot` и `amount`
- Смена исполнителя или оценки пересчитывает план. Смена ставки в проекте — план всех карточек этого исполнителя. Факт и старые списания не пересчитываются
- Без исполнителя план = 0
- Member создаёт, правит и удаляет только свои записи и только если он текущий исполнитель карточки
- Owner/Admin — любые записи на любых карточках (в том числе «за себя» на чужой)
- Перемещение — только между колонками этой доски; порядок в колонке — поле `position`
- Часы списания: `0.5 … 24`, шаг 0.5. Оценка: `0 … 1000`, шаг 0.5
- Колонки по умолчанию: «К выполнению», «В работе», «На проверке», «Готово» (`isDone` только у «Готово»)
- Owner/Admin: переименовать, порядок, добавить, удалить колонку. Удаление запрещено, если в колонке есть карточки
- Просрочка: `dueDate < сегодня` и карточка не в колонке с `isDone`
- Метки принадлежат доске. CRUD меток — Owner/Admin; назначить на карточку — Member+
- Комментарии: все кроме Viewer; без редактирования; удаляет автор либо Owner/Admin
- Релиз на карточке опционален: одна карточка — один релиз или без релиза

### Релиз

- Принадлежит проекту. Название уникально в рамках проекта (trim, без учёта регистра)
- Поля: название, дата (можно пустую), статус `planned` | `released`
- При создании статус всегда `planned`; поле статуса в форме create игнорируется. Смена статуса — отдельное действие Owner/Admin
- Карточка ссылается через `releaseId`. Без релиза допустимо
- Статус информационный: к `released` можно прикреплять карточки (хотфиксы). Смена статуса не двигает карточки по колонкам
- Создать, править, сменить статус, удалить — Owner/Admin
- Прикрепить и открепить карточку — кто может править карточки (Member+)
- Viewer только смотрит

### Удаление

- Команда — только Owner (каскадом проекты, карточки, релизы)
- Проект — Owner/Admin, каскадом колонки, карточки, релизы
- Релиз — Owner/Admin; карточки остаются, `releaseId` сбрасывается
- Карточка без списаний — Member/Admin/Owner; со списаниями — только Owner/Admin

## Экономика (бюджет проекта)

Валюта: **RUB**. Бюджет — целое число ≥ 0.

- **Бюджет проекта** — лимит в деньгах
- **Ставка** (руб/час) в проекте: персональная участника → иначе ставка его роли → иначе 0
- **План карточки** = оценка часов × ставка исполнителя
- **Факт** = сумма (часы списания × `rateSnapshot`)
- **Остаток** = лимит − факт
- Превышение бюджета — предупреждение, списания не блокируются

## Аналитика

Скоуп: один проект и период. Пресеты: 7 дней / 30 дней / квартал (от сегодня). Произвольный date range в v1 нет.

Деньги и ставки скрыты у Viewer. Member в аналитике видит часы всех; ₽ — только свои, плюс остаток проекта.

- Сводка, статусы колонок, риски, релизы «готово / всего» — **снимок сейчас**, не фильтр по дате
- «Готово» = колонка с `isDone`, не сравнение по имени
- Статусы — по колонкам единственной доски проекта; «без релиза» — отдельная строка
- План vs факт, загрузка, списания по неделям — списания с `workedAt` в периоде; план — текущие оценки
- Сгорание бюджета — всегда всё время (лимит vs суммарный факт), период не режет
- Риски: просрочено, срок на этой неделе, дыры (нет исполнителя / оценки / релиза)

Сводка: число карточек, просроченные, без исполнителя, без оценки, без релиза.

## Экраны MVP

| Экран | Содержание |
| --- | --- |
| **Вход** | Кнопка «Войти через Яндекс ID» |
| **Команды** | Список своих команд, создать команду |
| **Команда** | Участники, инвайты, список проектов, настройки (Owner: удаление) |
| **Принятие инвайта** | `/invite/:token` → OAuth, если нет сессии → вступление |
| **Проект** | `/projects/:id` — канбан; вкладки Доска / Релизы (если включены) / Аналитика / Настройки (owner/admin) |
| **Релиз** | Название, дата, статус, список карточек, прикрепление |
| **Карточка** | Модалка: исполнитель, срок, оценка, релиз, списания, метки, комментарии |
| **Аналитика** | Период, сводка, статусы, план/факт, бюджет, загрузка, релизы, списания, риски |

## Типичный сценарий

1. Войти через Яндекс ID
2. Создать команду
3. Пригласить участников одноразовой ссылкой (роль задаётся в инвайте)
4. Приглашённый открывает `/invite/:token` и вступает после OAuth
5. Создать проект — сразу открывается канбан; Owner задаёт бюджет
6. Создать релиз (название, дата; статус `planned`)
7. При необходимости настроить колонки на той же странице
8. Добавить карточки с исполнителем и оценкой часов, прикрепить к релизу
9. Открыть карточку модалкой, списывать часы по мере работы
10. Смотреть остаток бюджета и отчёты

## Деплой

| Параметр | Значение |
| --- | --- |
| **Хостинг** | VPS Beget, Ubuntu 26.04 |
| **Домен** | [taskmaster.shamilfrontend.ru](https://taskmaster.shamilfrontend.ru) |
| **Контейнеры** | Docker: frontend, backend, MongoDB |
| **Прокси / HTTPS** | Caddy (TLS и reverse proxy к frontend/backend) |
| **CI/CD** | GitHub Actions → SSH на VPS |

### Docker

- `frontend` — SPA (Vue 3)
- `backend` — API (Express)
- `mongodb` — БД (только внутри Compose, наружу не открывать)

Сборка и запуск через Docker Compose на VPS. Caddy терминирует HTTPS и проксирует на контейнеры.

`YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `JWT_SECRET` и `YANDEX_REDIRECT_URI` — GitHub Secrets; CI пишет их в `/opt/taskmaster/.env` на VPS.

### Первый деплой

1. DNS: A-запись `taskmaster` → IPv4 VPS. Проверка: `dig +short taskmaster.shamilfrontend.ru`
2. На VPS один раз (под `DEPLOY_USER`):

```bash
sudo apt-get update
sudo apt-get install -y git ca-certificates curl
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
sudo systemctl disable --now nginx apache2 2>/dev/null || true
```

Перелогинься, проверь `docker compose version`. Публичный ключ от `DEPLOY_SSH_KEY` — в `~/.ssh/authorized_keys`.

3. GitHub Secrets:

| Secret | Назначение |
| --- | --- |
| `DEPLOY_HOST` | Хост VPS |
| `DEPLOY_PORT` | SSH-порт |
| `DEPLOY_USER` | Пользователь SSH |
| `DEPLOY_SSH_KEY` | Приватный ключ для деплоя |
| `YANDEX_CLIENT_ID` | OAuth-приложение Яндекс ID |
| `YANDEX_CLIENT_SECRET` | Секрет OAuth-приложения |
| `JWT_SECRET` | `openssl rand -hex 32` |
| `MONGO_INITDB_ROOT_PASSWORD` | `openssl rand -hex 24` |
| `YANDEX_REDIRECT_URI` | `https://taskmaster.shamilfrontend.ru/api/auth/yandex/callback` |

4. oauth.yandex.ru: добавь тот же Callback URI. Локальный `http://localhost:3000/api/auth/yandex/callback` не удаляй.
5. Push в `main` → Actions → SSH → `git clone`/`pull` в `/opt/taskmaster` → `.env` → `docker compose up -d --build`
6. Проверка: `https://taskmaster.shamilfrontend.ru/api/health` → `{"ok":true}`

Если TLS не выдался — DNS ещё не дошёл или 80/443 закрыты.

## Вне v1

Не входит в первую версию: почта, уведомления, роли на проекте, несколько исполнителей на карточке, экспорт отчётов, смена Яндекс-аккаунта, привязка инвайта к email, произвольный период аналитики, редактирование комментариев, описание карточки.
